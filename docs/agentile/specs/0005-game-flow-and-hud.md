# Title screen, ready/pause/game-over flow, high score and retro polish

## Problem / why now

With rules and ghosts done, the missing piece is the wrapper that makes it a
game you launch and leave: a title screen, the READY! beat, pause, game over,
a persisted high score, and the last touches of arcade feel.

## Acceptance criteria

- [ ] State machine in `lib/flow.mjs` (tested): `title → ready → playing ⇄ paused → dying → (ready | gameover) → title`, `level-clear → ready`. `Enter`/`Space` starts, `p` or `Escape` pauses (Escape on title quits, `q` always quits after a confirm beat of 1 s hold on title only — no confirm during play).
- [ ] Title screen: "PACMAN" in `Theme.accent`, the four ghosts and Pac-Man in a classic roll-call (name, nickname, sprite in its theme colour), "PRESS ENTER" blinking, high score shown; an attract-mode demo (scripted inputs replaying deterministically) starts after 10 s idle.
- [ ] READY!: 2 s beat with the board drawn, ghosts in the house, "READY!" in `Theme.yellow`, then play. "GAME OVER" in `Theme.red` for 3 s before returning to title.
- [ ] High score persisted in `~/.local/state/pacman/highscore.json` via `lib/settings.mjs`; updated at game over and on level clear; shown in the HUD live when beaten.
- [ ] Pause overlay dims the board (`Theme.background` at 60 % alpha) with "PAUSED"; the loop and sounds stop.
- [ ] Retro polish, arcade style only: 1UP blink at 250 ms; optional scanline overlay toggled with `s` (persisted) drawn as 1-px lines at 15 % alpha of `Theme.darker_background`; the smooth mode ignores both. Scanlines are drawn in `PixelStage` above the upscaled layer, not in native units.
- [ ] Window title reflects state: `Pacman`, `Pacman — paused`.

## Scope boundary

**In scope:** flow states, title, attract demo, ready/game-over beats, pause, high score, scanlines, 1UP blink.

**Out of scope:** initials entry / high-score table (inbox), cutscenes (inbox), settings UI beyond keys.

## Edge cases and failure paths

- Window loses focus mid-game → auto-pause (Quickshell window `active` false).
- Corrupt `highscore.json` → treat as 0 and rewrite.
- Attract demo drifting from the maze if the maze changes: the demo input script is generated by the test suite from the current maze and stored with a maze checksum; mismatch → skip attract, log a warning.

## Affected areas

`lib/flow.mjs`, `lib/settings.mjs`, `lib/attract.mjs`, `tests/flow.test.mjs`, `tests/attract.test.mjs`, `app/Main.qml`, `app/render/Screens.js`, `app/render/Hud.js`, `app/PixelStage.qml` (scanlines).
