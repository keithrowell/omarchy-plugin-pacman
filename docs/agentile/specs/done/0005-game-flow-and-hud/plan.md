## Approach

### Flow state machine (`lib/flow.mjs`)

```
flow = { screen, ticks, idleTicks, attract: false, quitHoldTicks: 0 }
screen ∈ { "title", "ready", "playing", "paused", "dying", "level-clear", "gameover" }
```

Transitions (`flowAction(flow, action)` returns a new flow, ignores illegal
actions and returns the same object):

| From | Action | To | Notes |
|---|---|---|---|
| title | `start` | ready | caller creates a new game state |
| title | `attract` | ready (attract: true) | issued by `flowTick` when `idleTicks ≥ 600` |
| any attract screen | `any-key` | title | idle reset, attract false |
| playing, ready | `pause` | paused | `Escape`/`p`/focus loss |
| paused | `resume` | previous game screen | store `resumeTo` |
| paused | `toggle-pause` | resume | `p`/`Escape` |
| gameover | (`flowTick` after 180 ticks) | title | attract games too |
| title | `quit-hold` (per tick while `q` held) | — | `quitHoldTicks++`; caller quits at 60 |

`syncFlow(flow, phase)`: while in a game and not paused, map the game phase
(`ready/playing/dying/level-clear/game-over`) onto the screen so the renderer
has one source of truth; `game-over` enters `gameover` with `ticks = 0`.
`shouldStep(flow)` is true for `ready/playing/dying/level-clear` (the game
advances), false for `title/paused/gameover`. `flowTick` advances `ticks`,
`idleTicks` (title only) and fires `attract` / `title` transitions.

Keys, resolved in `Main.qml` with the flow screen:

| Key | title | playing / ready | paused | gameover | attract |
|---|---|---|---|---|---|
| Enter / Space | start | — | resume | (ignored; auto returns) | title |
| p | — | pause | resume | — | title |
| Escape | quit | pause | resume | — | title |
| q | hold 1 s → quit | quit at once | quit at once | quit at once | title |
| g | toggle mode | toggle | toggle | toggle | toggle |
| s | scanlines | **down** (WASD) | scanlines | scanlines | scanlines |
| arrows/hjkl/wasd | (any-key on attract) | move | — | — | title |

The spec gives `s` both to scanlines and, via WASD, to "down". Resolution:
`s` toggles scanlines on any screen where movement keys are inactive (title,
paused, gameover, attract) and stays "down" during play. Record this in the
spec at ship. The title shows the hint `S SCANLINES  G SMOOTH  HOLD Q QUIT`.

### Attract demo (`lib/attract.mjs`, `tools/gen-attract.mjs`)

The spec wants a script generated from the current maze and guarded by a
checksum. `tools/gen-attract.mjs`:

1. `createState(maze, { seed: 11, ready: false })`, autopilot = at each tile
   centre BFS to the nearest pellet (as the spec-0003 test does), feed the
   first step as `wantDir`; run up to 2,400 ticks or until `game-over`.
2. Run-length-encode the per-tick `wantDir` into `runs`, record
   `expectedScore`, `expectedTick`, `checksum = mazeChecksum(LEVEL_1)`.
3. Write `lib/attract-script.mjs` as `export const ATTRACT = {...}`.

`tests/attract.test.mjs` asserts: the committed checksum equals
`mazeChecksum(LEVEL_1)` (failure message: "maze changed: run
`node tools/gen-attract.mjs`"); replaying the script from the same seed
reproduces `expectedScore` at `expectedTick`; the run is ≥ 1,200 ticks; every
run's dir is a valid direction or null. At runtime `Main.qml` checks
`attractValid(ATTRACT, maze)`; on mismatch it logs a warning and the flow never
issues `attract` (pass `attract: false` into `createFlow`).

Attract playback: `flow.attract` true → the game state is created with the
script's seed and `ready: true`, the input each tick is `attractInput(ATTRACT,
state.tick)`, and the HUD shows a blinking `DEMO` banner (Screens). Any key
returns to the title. When the script runs out or the game reaches
`game-over`, `syncFlow` takes it to `gameover` → title as usual.

### High score

`Settings.qml` loads `highscore.json` (`parseHighScore`: integer ≥ 0 else 0,
floors floats; corrupt → 0 and rewritten on the next save). `createState`
receives `Settings.highScore`; `step` keeps `state.highScore = max(...)` so
the HUD shows it live. `Main.qml` on `game-over` and `level-clear` events
calls `Settings.setHighScore(state.highScore)` (writes only when it grew).
Attract games never persist.

### Ready, game over, pause

- `READY_TICKS = 120`. The board is drawn with ghosts in the house and
  `READY!` in `Theme.yellow` (already there).
- `gameover`: `GAME OVER` in `Theme.red` for 180 ticks, then title. During
  those ticks the game is not stepped (`shouldStep` false), so the last frame
  freezes with the text — matches the arcade.
- Pause: no `step`; `overlay` still repaints for the dim + text. `drawPaused`
  fills the board rect with `palette.dim` (`Theme.background` at 0.6 alpha:
  `Qt.rgba(c.r, c.g, c.b, 0.6)` built in `Main.qml` — a derived colour, not a
  literal) and centres `PAUSED` in `Theme.foreground` on the moat row. Pressed
  keys are cleared on pause and on focus loss so nothing sticks (closes the
  inbox stub about focus loss). Sound: nothing to stop yet; leave a comment
  where spec 0007 hooks in.
- Focus loss: `window.active` (Qt `Window.active`) false while `playing`/`ready`
  → `pause`. Do not auto-resume.

### Title screen (`Screens.drawTitle`)

Native units, arcade font: `PACMAN` at 16 px in `Theme.accent` centred at
y = 40; roll-call rows from y = 88, 24 px apart: ghost sprite (from
`Sprites.drawGhost` with a static ghost object facing right) at x = 40, name at
x = 64 in the ghost's colour, nickname in quotes at x = 136 in
`Theme.foreground`: BLINKY "SHADOW", PINKY "SPEEDY", INKY "BASHFUL", CLYDE
"POKEY"; then Pac-Man's wedge with `PACMAN` in `Theme.yellow`. Below: `HIGH
SCORE nnnnn` in `Theme.foreground` at y = 208; `PRESS ENTER` blinking every 500
ms in `Theme.accent` at y = 232; the key hint in `Theme.muted` at y = 272.
While `q` is held, draw a `QUIT` progress bar (width ∝ `quitHoldTicks / 60`) in
`Theme.red` at y = 256.

### Retro polish

- 1UP blink: `Hud.drawHud` gets `blinkOn` (`floor(timeMs / 250) % 2 === 0`)
  and `arcade`; `1UP` is drawn when `!arcade || blinkOn`.
- Scanlines: `PixelStage` draws, above the scene and only in arcade mode when
  `scanlines` is true, one horizontal line per native row at device-pixel
  positions `y = row × k` (in logical units `row × k / dpr`), `lineWidth = 1 /
  dpr`, `strokeStyle` = `scanlineColor` at `scanlineAlpha` (`Qt.rgba(...)` in the
  stage from the colour property). Redrawn when `k`, size, mode or the toggle
  changes. `Main.qml` binds `scanlineColor: Theme.darker_background`,
  `scanlines: Settings.scanlines`. Smooth mode: nothing drawn. The F12 grab
  must still be measured: with scanlines on, blocks are no longer uniform, so
  measure with them off (default) and once with them on to eyeball the look.
- Window title: `title: flow.screen === "paused" ? "Pacman — paused" : "Pacman"`.

### Main.qml structure

Keep the tick loop; wrap it: `if (Flow.shouldStep(flow)) { … step … }`. After
the loop `flow = Flow.syncFlow(flow, state.phase)` and `flow =
Flow.flowTick(flow, ticksThisFrame)`; on a `title` transition from `gameover`,
persist the high score. `start` creates `Game.createState(maze, { highScore:
Settings.highScore })`. Draw dispatch by `flow.screen`: `title` → Screens
only (no board); everything else → board + sprites + HUD, plus `drawPaused`
when paused, `drawAttractBanner` when `flow.attract`.

## Test strategy

- `flow.test.mjs`: every legal transition in the table; illegal ones return
  the same object; `title` idle 599 ticks stays, 600 → `ready` with
  `attract`; `any-key` during attract → title with idle 0; `pause` from

- `game.test.mjs`: `createState(maze, { highScore: 900 })` shows 900; eating

## Risks and unknowns

- **Focus signal under Quickshell**: `FloatingWindow` exposes the Qt window
  via `window.active`? If not, use `Window.active` from the `QtQuick.Window`
  attached property on the content item, or `input.activeFocus`. Verify with
  a log line; if none works, fall back to `activeFocus` of the `FocusScope`.
- **Scanline crispness at DPR 1.6**: a 1-device-px line at fractional logical
  coordinates may blur to two rows; acceptable for a 15 % overlay, but check
  the grab. If it looks bad, draw the lines into a second low-res layer at
  native height × k … keep it simple first.
- **Attract determinism across the QML/Node boundary**: the game is pure and
  the RNG is seeded, so the replay in QML must match Node; the test pins the
  expected score, and `Main.qml` logs a warning if the live attract run's
  score at `expectedTick` differs (debug mode).
- **Canvas font at 16 px**: the pixel font scales cleanly at integer
  multiples; 16 px is 2×.
- **Key hold detection for `q`** relies on release events; a focus loss
  mid-hold must reset `quitHoldTicks` (do it in the same focus-loss handler).

## As built (recorded at ship)

- `s` toggles scanlines only where movement keys are inactive (title,
  paused, gameover, demo); during play it is WASD down. The title hint says so.
- Focus-loss auto-pause is skipped for the whole session when a
  `PACMAN_DEBUG_KEYS` script was given (a stray click paused an unattended
  run); the reviewer asked for it to be narrowed to "while the script runs".
- The attract generator uses `ready: true` like playback so the replay is
  tick-aligned; the committed script ends by the 2,400-tick cap in `playing`,
  handled by an `attract-end` action.
- `attractValid` takes the maze text (the checksum is over the text).
- Title hints are on two lines; the quit bar sits at y 248.
- The high score is also saved on `q` mid-game.
- The frame loop keeps running while paused (only `step` stops); restarting
  `FrameAnimation` would burst up to 250 ms of ticks on resume.
- Grabs were taken under the decorative-stitch theme, whose cyan equals its
  accent, so Inky merges with the title colour there.
